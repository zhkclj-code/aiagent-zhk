### python基础
1. 可以搞一个虚拟环境给当前项目，也就是.venv，包含python环境、所需的lib包等
2. 对象.方法名(不带括号)，比如student.introduce，这是代表方法引用，而不是调用方法，这么写也不会报错
3. 所有实例方法，第一个参数都需要self，不然传参会有问题，调用时默认都会给当前调用对象传作第一个参数（隐式）
4. __new__和__init__，有些只有__new__有些只有__init__？一个是创建对象分配内存，一个是初始化实例，给属性赋值，只有__new__的一般不可变对象居多，比如str、tuple，一旦创建对象了，就不许修改属性，如果看似可变，实则内部是重新创建了新对象
5. 为什么容器类对象有时是通过自身.方法()调用，而有些则是通过统一的方法调用，比如len(x)，有时不知道哪些通过方法直接调用，哪些可以通过对象点出来？这是因为有些是该对象自身特有的方法，比如字典dict的items()，只有他才有，而像len()这是所有容器共有的特性，所以提出来单独作为一个内置方法，不需要每个容器类型都实现一遍，python有64个内置函数
   1. 一般内置函数返回新对象，而实例方法则在原对象修改
   2. 内置函数通用，实例方法特有
6. 在参数列表中/和*的作用是限位符，不接收参数，/保证前面都是位置传参不能用关键字传参，*之后只能用关键字传参，两个中间随便传
7. 字典和集合推导式都是使用{}，只是有没有:的区别，{}创建默认是字典，空集合只能set()；
8. 属性装饰器@property和@属性名.setter的方法名都得是属性名，属性需要避免同名冲突
   ```python
    @property
    def price(self) -> float:
        return self.price  # ❌ 调用自己 → 无限递归(会触发property拦截)
   ```
9.  如果setter中有值校验逻辑，在init中可以通过托管属性触发setter验证，比如self.price = price触发，真实的值存在self._price中
10. 装饰器的包装函数为什么要用`func(*args, **kwargs)`转发参数？`args`是位置参数组成的元组，`kwargs`是关键字参数组成的字典；`*`和`**`会分别将它们解包，还原被装饰函数收到的参数。写成`func(args, kwargs)`会把二者当作两个普通的位置参数传入，通常会导致参数数量或类型不匹配
11. 上下文管理器的`__enter__`一定要返回`self`吗？不一定。`__enter__`的返回值会赋给`with ... as ...`中`as`后面的变量；只有希望通过该变量使用当前管理器对象时才返回`self`，也可以返回其他资源对象。如果没有`as`变量需要使用，也可以不显式返回值，如果需要使用一定要返回
12. `with`代码块内发生异常后，`__exit__`执行完还会继续抛出异常吗？`__exit__(exc_type, exc, tb)`会先收到异常信息并完成清理；如果它返回`True`，异常会被抑制，如果返回`False`或`None`，原异常会在`__exit__`执行完后自动继续向外传播，不需要在`finally`中手动重新抛出
13. 被`@contextmanager`装饰的生成器函数为什么要配合`with`使用？调用它只会创建一个`_GeneratorContextManager`上下文管理器对象，不会按上下文管理流程执行函数体。进入`with`时，代码执行到`yield`并进入代码块；正常退出时再从`yield`后继续执行。如果代码块抛出异常，异常会被注入到`yield`处，因此必须把清理逻辑放在`try...finally`的`finally`中，才能保证异常退出时也会执行
14. `time.strftime()`的日期时间格式为什么不能写成`yyyy-MM-dd`？它使用带`%`的格式指令，例如`%Y-%m-%d %H:%M:%S`；`yyyy-MM-dd`不会被识别为“年-月-日”格式，而会基本按普通字符原样输出
15. 使用`csv`模块写文件时为什么推荐给`open()`传`newline=''`？`csv`模块会自行生成记录分隔符，`newline=''`可以关闭文本文件层的换行转换，避免两层换行处理叠加。在Windows等使用`\r\n`的平台上，不这样做容易在每条CSV记录之间出现额外空行；读取CSV时也建议这样打开文件，以便`csv`模块正确处理换行
